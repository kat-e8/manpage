Reaching Clubuntu

Four separate obstacles stood between "I need to copy two files to clubuntu" and it actually happening. None were about the files.

host: clubuntu.dala-cirius.ts.net 2026-08-16
01

The goal

Place db/schema.sql and coder_commands.xlsx at /opt/docker/manpage on clubuntu — the deploy compose file needs both there before its first run. Getting there required fixing SSH access, then fixing filesystem permissions, as two separate problems.

02

Obstacle 1 — no key authorized yet

SSH login by key works by proving possession of a private key without ever transmitting it. The public half has to be listed in the target account's authorized_keys first — it wasn't, so every connection attempt failed before anything else could happen.

03

Obstacles 2 & 3 — no real terminal, then a key too long to type

  • Password auth failed silently. No visible prompt, immediate rejection — not a wrong password, but this tool's command relay not providing SSH a real interactive terminal to prompt into at all.
  • The existing key was impractical to hand-type. A 4096-bit RSA public key runs to ~3000 characters — the target session could be typed into but not pasted into (Ctrl+V and right-click both failed there).
  • Fix, two parts: generated a dedicated ED25519 key just for this link — its public half is one short, typeable line — and found Shift+Insert worked as an alternate paste binding in that session anyway, making the whole block pasteable in one shot.
04

Obstacle 4 — logged in, still blocked

SSH decides who gets in. Once in, what that user can touch is a completely separate system — ordinary Unix ownership and permission bits, checked by the kernel on every file operation, with no awareness of how you authenticated.

05

The copy itself — scp is SSH, not a separate protocol

scp isn't a different tool bolted onto SSH — it's SSH's own file-transfer mode, reusing the exact same encrypted, authenticated connection from §02. No second login, no second key check: once the connection from §02 is open, the same channel just carries file bytes instead of (or alongside) a shell session.
