Standing Up the Runner

What the self-hosted runner actually is on disk, the user-isolation decision behind it, and the four-phase install. Verification appended once each phase is confirmed run.

host: clubuntu.dala-cirius.ts.net 2026-08-16
01

The decision: a dedicated user, not katlego

katlego already has everything technically needed — docker-group membership, ownership of the deploy directory. Using it would've meant zero new setup. Chose the more isolated path instead, on purpose.

02

What the runner actually is, on disk

Not a system service that already exists — a plain directory of files, downloaded once, that GitHub's Actions backend and a small local agent both know how to talk to.

03

The four phases

Phase 1 — user, docker access, bridge to the deploy directory
sudo useradd --system --create-home --home-dir /opt/actions-runner --shell /usr/sbin/nologin ghrunner
sudo usermod -aG docker ghrunner
sudo usermod -aG katlego ghrunner
sudo chmod -R g+rwX /opt/docker/manpage
sudo chmod g+s /opt/docker/manpage /opt/docker/manpage/db
Phase 3 — configure, as ghrunner, with the required label
sudo -u ghrunner -i
cd /opt/actions-runner
# GitHub's download + extract commands go here, unmodified
./config.sh --url https://github.com/kat-e8/manpage --token <TOKEN> \
  --name clubuntu --labels clubuntu --unattended
exit
Phase 4 — install as a systemd service
cd /opt/actions-runner
sudo ./svc.sh install ghrunner
sudo ./svc.sh start
sudo ./svc.sh status

Phase 2 — generating the registration token — happens entirely in GitHub's web UI (repo Settings → Actions → Runners → New self-hosted runner) and isn't a command to log.
