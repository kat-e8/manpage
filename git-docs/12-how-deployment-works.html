Rolling back

Identical to steps ⑤–⑧, with one substitution: step ⑤ becomes git tag vX.Y.Z-rollback <older-commit-sha> instead of the newest commit. Every step after that is the same code path, unaware it's "a rollback" — it costs one pull, never a rebuild, because that older SHA's images are still sitting in the registry from whenever they were originally built.

One exception learned the hard way: re-pushing an already-existing, unchanged tag triggers nothing — no ref change, no push event. Redeploying the same version again means deleting and recreating that tag first.

04

What never crosses which boundary

  • The laptop's source tree never reaches clubuntu — only images, and only docker-compose.deploy.yml, freshly copied out of each disposable checkout.
  • .env, db/schema.sql, coder_commands.xlsx live only on clubuntu, permanently — never in git, never rebuilt, never touched by either workflow.
  • clubuntu never receives an inbound connection from GitHub — the runner always polls outward, never the other way around.
